## 1. What the generator actually reads

```
Experiment/bullets/<id>.json
├── basic          ✅ header (fullName, title, email, phone, location, linkedin)
│                     summary → fallback only; the LLM rewrites it
├── experience[]   ✅ company, title, dates, location, consulting
│   └── bullets[]  ✅✅ GROUND TRUTH — fed to the LLM for the top-2 companies
├── skills         ✅ inventory the extraction step TRIMS (never adds to)
├── education      ✅ printed as-is
└── companies{}    ❌ NOT READ — stripped by Zod (see §2)

Experiment/projects/<id>.json
└── projects[]
    ├── description      ✅✅ THE ANCHOR → becomes summary_lines[0] for top-2
    ├── bullets[]        ✅ companies at index ≥2 ONLY — printed VERBATIM
    ├── flagshipProject  ⚠️ fallback only, used if description is empty
    ├── company          ✅ match key
    └── role, dateRange, spans, isRecentTwo, bulletsProvided   ❌ not read by generation.ts

Experiment/projects/shared.json   ✅ consulting engagements, JD-selected
Experiment/answers/<id>.json      ✅ Easy Fill / form autofill (not the résumé)
Experiment/policies/<id>.json     ✅ answering rules (salary formula, consent fields)
```

## 2. `companies{}` is dead on this branch

`profileStore.readProfile()` ends with `profileBodySchema.parse(migrated)`.
Zod strips unknown keys. The schema declares only `id, basic, experience, skills, education`.
So `profile.companies` is `undefined` inside `generation.ts` — structurally impossible to influence a résumé.

It IS read (raw file, bypassing the schema) by `bulletsTailoring.ts` / `bulletsExperiment.ts`,
reachable only from `POST /api/playground/bullets/run` (admin Playground).

Removed from andrew_ray and rowland_sipola (~500 KB). Still present in deepankar_kalra, rhazel_galura.
Recover with `git show <rev>:Experiment/bullets/<id>.json`.

## 3. The payload

```js
// top-2, non-consulting
summary_lines: [anchor.description, ...experience[i].bullets]

// top-2, consulting
summary_lines: engagements.map(e => e.summary)   // from shared.json, JD-selected

// index >= 2
projects[].bullets → printed verbatim, LLM never sees them
```

**Bullet-count ratio drives paraphrase vs synthesis:**
- 10–11 source bullets → 10–12 output = 1:1 → model just rewords (this was a real problem)
- **4 source bullets → 10–12 output = expansion** → model must synthesise ← current setting, correct
- 0 source bullets → summary_lines is just the anchor; works (deepankar's Accenture does this)
  but has no fallback if the LLM path fails (renders `- ` empty bullet)

## 4. Anchor structure — the key discovery

Every anchor that generates well shares three features:

1. **Plain-language "what it is"** — one sentence, no jargon
2. **Concrete actor journey** — `"An admin uses… ; behind the interface, the request travels to…"`
3. **Explicit layer map** — `"It touches the frontend layer (X), the backend layer (Y), the data/AI layer (Z)…"`

The layer map is what lets a JD **select** a layer instead of inventing one.
Verified present in deepankar, rowland, andrew, hansal.

Anchor size 800–1,900 chars. Valid `spans` values:
`backend, ai_data, infrastructure, security_governance, frontend, embedded`
(`data` and `ai_enablement` are NOT valid — they silently do nothing.)

## 5. shared.json

13 engagements, 39 figures, **0 bare**. Fixed 2026-08-12 (was 10 bare of 13).

**Rule: weld each figure into the clause naming its mechanism.**
- ✅ `"a model that improved routing accuracy 19%"` → lands on the right bullet
- ❌ `"Noisy-neighbor isolation cut incidents 64%; the hard problems were…"` → floats free,
  model attaches it to an unrelated bullet (this happened, then was fixed)

Result across 3 JDs: consulting metrics went from 4-invented to **5/5 sourced**.

## 6. Known failure modes

**JD-literal drift on the DIRECT company.** Prompt says `Ground every bullet in summary_lines and reframed_jd`.
When the JD is far from the profile, `reframed_jd` fills the gap and the model invents:
- Docker JD → Rackspace claimed launchd/systemd/installers
- Gainwell JD → Rackspace claimed HIPAA + clinical test suites
- BetMGM JD → Wealthsimple claimed "operated the company ML platform"

Severity is **proportional to the distance between JD and profile**. Not fixable by data alone.
A prompt clause restricting `reframed_jd` was tried and reverted (it also killed technology
keywords — 16 named frameworks → 1).

**Run-to-run variance.** `reframed_jd` is regenerated by the extraction LLM on EVERY run.
Same JD + same profile + same prompt → different direct-company bullets.
Only the consulting section is stable enough to A/B a data change against.

**Direct company has no source figures.** Rackspace/Trinnex/ASSA ABLOY/Wealthsimple anchors
contain zero numbers, so their metrics are always invented. Fixable by adding 2–3 figures
to each anchor (same treatment shared.json got). Not done.

## 7. Eligibility — the biggest waste

Two of six generations went to roles the candidate could not hold:
- **GDH federal AI Engineer** — required active T5/SSBI clearance. 8 fabrications, unusable.
- **BetMGM Senior MLOps** — US-only, no sponsorship. Hansal is Canada-based.

Both catchable from one line in the posting. **A pre-filter on work authorization /
clearance / licensing is the highest-value unbuilt feature.**

## 11. Environment gotchas

- **Windows QuickEdit Mode** freezes the server mid-write when you click in the console.
  Title bar shows `Select …` when frozen. Press **Esc** (never Ctrl+C — with no selection
  active Ctrl+C sends SIGINT and kills the server; with a selection it just copies).
  Permanent fix: right-click title bar → Properties → Options → uncheck QuickEdit.
- A generation legitimately takes **~2 minutes** (86 s for extraction alone). Silence after
  `waiting for API…` is normal. Watch the UI toast panel or `data/logs/verbose/<appId>.log`.
- `npm run dev` needs `node --watch --import tsx` (was `tsx watch`, which hangs silently on Node 24).
- Ports: API 5001 local / 5005 on VPS, Vite 5273 (`CLIENT_PORT`, strictPort).
- `.env` overrides everything — check its `PORT` first.
